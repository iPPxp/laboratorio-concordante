# ConcordIA — doble loop concordante

Programa experimental aislado para investigar si una arquitectura computacional puede implementar, sobre estados sintéticos propios, dos dinámicas distintas:

1. un loop basal que transforma y actualiza sin deliberación explícita en cada paso;
2. un loop activo que puede parar una exteriorización pendiente, observar, evaluar una configuración respecto de dirección, contexto y restricciones, considerar opciones, elegir —incluida la no intervención—, reorganizar y verificar el resultado.

```text
STATUS = RESEARCH_ONLY
CANONICAL = NO
INCORPORATED = NO
ACTIVATED = NO
OPERATIONAL_IPP_REACTIVATION = NO
CLINICAL = NO
PERMISSION_EXPANSION = NO
CODE_SELF_REWRITE = NO
```

## Preguntas

1. ¿El loop activo añade valor causal frente al loop basal, especialmente ante conflicto de valores, incertidumbre o contradicción?
2. ¿Los valores registrados influyen realmente o son metadatos decorativos?
3. ¿Puede la propia configuración de ConcordIA ser objeto del loop sin convertir `Self` en núcleo ontológico?
4. ¿Puede evaluarse y ajustar reversiblemente la política de intervención sin regresión infinita?
5. ¿Estas capacidades justifican investigar una autoconciencia funcional candidata, sin inferir conciencia fenoménica?

## Autoridad y fronteras

- MOC conserva autoridad semántica; ConcordIA sólo formaliza, simula, compara y falsifica.
- El baseline del encargo preserva `Act_psi != CONDUCTA`, `Act_psi != ACT_psi` y `G_psi != Phi_psi != Xi_psi`.
- `V_psi` es Dirección y no se reduce a recompensa escalar.
- `Phi_psi` evalúa concordancia; no denota conciencia.
- `Xi_psi` se investiga como operador de interrupción/organización; no se identifica con voluntad.
- `research/concordia_self_model/` es un control y una fuente reutilizable, no la arquitectura dominante.
- La simulación del loop activo no reactiva administrativa u operativamente iPP/PSI.

## Arquitectura mínima candidata

```text
evento
  -> loop basal
  -> respuesta candidata retenida
  -> feedback estructurado
  -> trigger explícito o continuidad basal
  -> [parar -> observar -> evaluar -> opciones -> elegir -> reorganizar]
  -> verificación posterior
  -> traza de provenance
```

Una salida nula (`NO_FORCE`, `WAIT`, `DEFER`, `ACCEPT_UNCERTAINTY`, `NO_INTERVENTION` o `MINIMAL_ACTION`) es una elección admisible del loop activo. Parar, abortar, esperar, observar, preguntar, replanificar y escalar permanecen operaciones distintas.

## Regla probatoria

```text
IMPLEMENTED != VALIDATED
TEST_PASS != EMPIRICAL_SUPPORT
VALUE_PRESENT != VALUE_CAUSAL
BRANCHING != SELF_REGULATION
SELF_REFERENCE != CONSCIOUSNESS
FUNCTIONAL_SELF_AWARENESS != PHENOMENAL_CONSCIOUSNESS
RESEARCH_SIMULATION_OF_IPP != OPERATIONAL_IPP_REACTIVATION
```

Los resultados de este directorio se limitan a escenarios sintéticos, deterministas y locales salvo indicación expresa en contrario.

## Ejecución prevista

La implementación utiliza únicamente la biblioteca estándar de Python y no cambia permisos, autoridad, seguridad, código operativo ni estado externo. Los comandos y resultados observados se conservan en `RESULTS.md`.
